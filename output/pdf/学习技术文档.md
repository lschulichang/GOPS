# GOPS 学习技术文档：按源码追 PPO、SAC 与车辆环境

> 适合第一次读强化学习工程代码的同学。对应 [一周学习计划](output/pdf/学习计划) 和 [小白入门导读 PDF](output/pdf/GOPS_小白入门导读_PPO_SAC_车辆跟踪.pdf)。每次约 1 小时，先读数据流，再补公式。本周只阅读和画图，不要求训练出可用策略。

## 0. 先记住这张地图

```text
训练入口 example_train/
  └─ create_pkg/ 根据字符串参数创建环境、算法、采样器、训练器
      └─ Trainer.train() / Trainer.step() 安排一次迭代
          ├─ Sampler：策略根据 obs 选 act，再调用 env.step(act)
          ├─ PPO：整理当前采样数据，算 adv/ret，然后更新
          └─ SAC：经验进入 ReplayBuffer，随机抽取后更新

环境侧：车辆状态 + 参考轨迹 → obs；接收 act → 状态变化 + rew
```

初读时只需认识五个量：`obs` 是当前观测，`act` 是动作，`rew` 是奖励，`done` 表示本回合是否结束，`next_obs` 是执行动作后的观测。SAC 的回放缓存把 `next_obs` 存成键 `obs2`。**车辆的完整物理状态不等于策略看到的 `obs`。**

## 第 1 次：先找到“谁调用谁”

**目标：**不深入公式，能从训练入口指出一次采样和一次更新发生在哪里。

按以下顺序打开文件，推荐在 Cursor 用 `Ctrl+P` 输入文件名，用 `Ctrl+F` 搜索函数名：

1. [PPO 入口](example_train/ppo/ppo_mlp_pendulum_onserial.py)：找 `env_id="gym_pendulum"`、`algorithm="PPO"`、`trainer="on_serial_trainer"`，再看文件末尾的 `create_*` 和 `trainer.train()`。

3. [create_trainer.py](gops/create_pkg/create_trainer.py)：只看 `create_trainer()`。它根据 `trainer` 名称找到类；`on` 分支不把回放缓存交给训练器，`off` 分支会传入缓存。
4. [on_serial_trainer.py](gops/trainer/on_serial_trainer.py) 与 [off_serial_trainer.py](gops/trainer/off_serial_trainer.py)：搜索 `train()` 和 `step()`。注意 `step()` 中采样器与 `alg.local_update()` 的先后关系。

```text
PPO 入口 → OnSerialTrainer.step()
              → sampler.sample_with_replay_format()
              → PPO.local_update(当前样本)

SAC 入口 → OffSerialTrainer.step()
              → sampler.sample() → buffer.add_batch()

```

## 第 2 次：PPO 的一批数据怎样用于更新

**先看这条路径：**

1. [on_serial_trainer.py](gops/trainer/on_serial_trainer.py)：从 `step()` 找到 `sample_with_replay_format()` 和 `alg.local_update()`。
2. [sampler/base.py](gops/trainer/sampler/base.py)：看 `_step()`。策略网络接收 `obs`，动作分布给出 `action` 和 `logp`，然后调用环境的 `step(action)`，组成一条 `Experience`。
3. [sampler/on_sampler.py](gops/trainer/sampler/on_sampler.py)：依次看 `_sample()`、`_process_experiences()`、`_finish_trajs()`。它把多步经验整理为批量数据，并计算 `adv`、`ret`。
4. [algorithm/ppo.py](gops/algorithm/ppo.py)：看 `local_update()` 和 `_compute_loss()`。整批数据被切为小批量，重复计算损失并更新策略网络、价值网络。

| 字段 | 从哪里来 | 更新时做什么 |
| --- | --- | --- |
| `obs / act / rew / done` | `sampler/base.py` 调用环境得到经验 | 标识当时看到了什么、做了什么、得到什么反馈 |
| 旧 `logp` | 采样动作时由动作分布给出 | 与更新时重新计算的动作对数概率比较 |
| `adv` | `OnSampler._finish_trajs()` 根据奖励和价值估计计算 | 告诉策略更新这次动作相对估计有多好 |
| `ret` | 同一个轨迹收尾函数计算 | 给价值网络提供学习目标 |

读 `_compute_loss()` 时，先认出 `ratio = exp(新 logp - 旧 logp)`，再看它与 `adv` 如何进入截断策略损失。此时不需要推导完整公式。

**论文安排：**在这次读源码时，用约 20 分钟看 PPO 论文的摘要、算法流程和截断目标函数；第 5 次比较数据流时再回看。先把论文里的 `ratio`、`advantage` 对上代码中的变量。

**今天的笔记：**画出“`obs` → 动作与旧 `logp` → 环境奖励 → `adv/ret` → 小批量损失 → 参数更新”。

**自检：**旧 `logp` 和新 `logp` 是否在同一时刻计算？`adv/ret` 在哪个函数产生？

## 第 3 次：SAC 的经验怎样进入回放缓存

**按经验的移动顺序读：**

1. [off_serial_trainer.py](gops/trainer/off_serial_trainer.py)：先看 `__init__()` 的缓存预热，再看 `step()` 的“采样、入库、回放、更新”。
2. [sampler/off_sampler.py](gops/trainer/sampler/off_sampler.py)：`_sample()` 反复调用共同的 `_step()`。不明白一条经验怎样产生时，回看 [sampler/base.py](gops/trainer/sampler/base.py)。
3. [buffer/replay_buffer.py](gops/trainer/buffer/replay_buffer.py)：看 `store()`、`add_batch()`、`sample_batch()`。`next_obs` 存入缓存时对应 `obs2`；随机抽样后变成训练批量。
4. [algorithm/sac.py](gops/algorithm/sac.py)：按 `local_update()` → `_compute_gradient()` → `_compute_loss_q()`、`_compute_loss_policy()` → `_update()` 阅读。

```text
新经验 Experience(obs, act, rew, done, next_obs, logp, ...)
  → ReplayBuffer 存为 obs / act / rew / done / obs2 / logp / ...
  → sample_batch(replay_batch_size)
  → SAC：两个 Q 网络计算价值，策略产生新动作，优化器更新参数
  → 目标 Q 网络缓慢跟随当前 Q 网络
```

不要混淆三个数量：`sample_batch_size` 是一次新采样的数量；`buffer_warm_size` 是开始常规更新前先存入缓存的数量；`replay_batch_size` 是每次更新从缓存中抽取的数量。SAC 的 Q 损失读取 `obs、act、rew、obs2、done`；策略更新还会用当前策略重新采样得到 `new_act、new_logp`。

**今天的笔记：**画一条经验从 `env.step()` 进入 `ReplayBuffer`，再被抽出来更新 Q 网络、策略网络和目标网络的箭头图。

**自检：**缓存里为什么可能有旧经验？`obs2` 是什么？`new_logp` 在哪一步产生？

## 第 4 次：拆开三自由度车辆跟踪环境

这次只读环境侧，不把倒立摆训练脚本的参数直接套给车辆。按下面顺序读：

1. [veh3dof_tracking.py](gops/env/env_gen_ocp/veh3dof_tracking.py)：找 `Veh3DoFTracking`、`reset()`、`_get_obs()`、`_get_reward()`、`_get_terminated()`。
2. [robot/veh3dof.py](gops/env/env_gen_ocp/robot/veh3dof.py)：看 `Veh3DoF.step()`；状态是 `[x, y, phi, u, v, w]`，动作是 `[steer, ax]`。
3. [context/ref_traj.py](gops/env/env_gen_ocp/context/ref_traj.py)：看 `RefTrajContext.reset()`、`step()`，理解参考点怎样生成和向前移动。
4. [pyth_base.py](gops/env/env_gen_ocp/pyth_base.py)：找 `Env.step()`。这是车辆任务继承来的公共流程。

| 对象 | 初学时怎么理解 | 主要位置 |
| --- | --- | --- |
| `robot.state` | 车辆完整物理状态：位置、航向、纵横向运动和横摆 | `robot/veh3dof.py` |
| `context.state.reference` | 当前及未来的参考位置、航向和速度 | `context/ref_traj.py` |
| `obs` | 车辆与参考轨迹的相对信息，供策略使用 | `veh3dof_tracking.py::_get_obs()` |
| `action` | 转向 `steer` 与纵向加速度 `ax` | `robot/veh3dof.py::step()` |
| `reward` | 位置、航向、速度误差和控制动作等的代价取负 | `veh3dof_tracking.py::_get_reward()` |

默认 `pre_horizon=10`，观测由 6 个当前相对量加 10 组未来参考量构成，共 `6 + 4×10 = 46` 维。读 `Env.step()` 要留意时间顺序：**先用当前状态和动作算奖励，再推进车辆和参考轨迹，再检查终止，最后返回下一观测**。终止时还会扣除惩罚。因此，本步 `reward` 与返回的 `next_obs` 对应的状态时刻不同。

**今天的笔记：**做一张“变量｜含义｜由谁产生｜在哪使用”的表，填入车辆状态、参考点、观测、动作、奖励、结束标志。

**自检：**为什么策略的 `obs` 不是直接等于 6 维车辆状态？参考轨迹怎样影响观测和奖励？

## 第 5 次：把三条线连起来讲

不再打开新文件。用前四次的图，完成这张对照表：

| 问题 | PPO 示例 | SAC 示例 |
| --- | --- | --- |
| 谁采样？ | `OnSampler` | `OffSampler` |
| 更新前的数据在哪里？ | 当前策略刚采的一批轨迹；采样器补出 `adv/ret` | 新经验写入 `ReplayBuffer`，随后随机抽样 |
| 更新重点 | 旧/新动作概率之比、`adv`、`ret` | 回放经验、两个 Q 网络、策略与目标网络 |
| 更新入口 | `PPO.local_update()` | `SAC.local_update()` |

再用车辆环境讲共同交互：`obs → 策略给 steer/ax → Env.step() → 车辆状态与参考轨迹推进 → reward、next_obs`。本仓库的两个指定 PPO/SAC 示例使用的是 `gym_pendulum`；这里讲的是通用数据流，不代表已有对应车辆训练脚本。

3. SAC 的新经验怎样入库、抽样并用于更新？
4. 车辆参考轨迹怎样影响 `obs` 和 `reward`？
